# 차곡 · Chagok

은행 거래내역과 별도 지출을 모아 월별 정산·배분·마감까지 처리하는 로컬 Electron 앱입니다. 실행하면 마지막 작업 화면으로 진입합니다. 서버와 TanStack Query를 사용하지 않습니다.

## 현재 기능

- `.xlsx` 파일 선택, 거래 양식 인식, 시트·월별 미리보기와 선택 저장
- SQLite 거래 저장, 월별 조회, 내용·메모·계좌 검색, 입금·출금·확인 필요 필터, 50건 단위 페이지
- 거래 상세에서 원본 셀 값과 파일명·시트·행 번호 확인
- 같은 계좌의 재가져오기와 겹치는 거래 중복 제외
- 마지막 정산월·메뉴 저장과 복원
- 선택한 달의 전체 거래를 `거래내역`·`월별 요약` 2개 시트의 엑셀로 내보내기
- 별도 현금·카드·기타 지출 입력·수정·삭제, 사용일·정산월·결제자·결제수단·메모와 영수증 보관
- 수입·지출·이체·정산 제외, 항목 관리, 금액 보정·확정과 일괄 분류
- 거래 내용·메모·상대 예금주를 조건으로 하는 반복 분류 규칙과 가져오기 시 자동 제안
- 별도 지출과 통장 출금의 금액별 연결, 여러 카드 사용 건과 카드대금 한 건 연결
- 정산 수입·현금·카드·기타 지출·잔액, 대상별 비율과 원 단위 배분
- 일별 추이·지출 항목·최근 6개월 비교 차트와 내역·정산월 이동
- 월 마감·재개방 사유·마감본 보관·변경 전후 이력, 기존 정산표 배치로 엑셀 출력
- 영수증과 DB 전체 백업·복원, 파일 무결성 검사와 복원 전 장부 보관

거래내역 화면의 입출금 요약은 **엑셀 원본의 통장 흐름**, 월별 정산 화면은 **보정·분류한 정산 금액**입니다. 원본의 빈 금액을 보정해도 원본 자료는 변경하지 않습니다.

## 아이콘과 디자인 테마

- **녹색과 종이색**: 주요 색 `#285341`, 작업 배경 `#F5F4EE`, 카드 `#FFFEFA`. 선택 메뉴는 옅은 세이지, 확인이 필요한 경고는 테라코타 계열을 사용합니다. shadcn 기본 컴포넌트의 테마 토큰으로 적용합니다.
- **쌓인 전표 아이콘**: `src/domains/dashboard/assets/chagok-icon.svg`가 원본입니다. 사이드바와 창·작업 표시줄·실행 파일에서 같은 디자인을 사용합니다.
- **숫자와 차트**: 정산 잔액·배분액은 녹색과 큰 숫자로 강조합니다. 차트는 수입 녹색, 지출 흙색으로 구분하고 범례를 표시합니다.
- **내장 서체**: Pretendard Variable v1.3.9를 포함해 인터넷 없이 사용합니다. [공식 배포처](https://github.com/orioncactus/pretendard/tree/v1.3.9), 라이선스는 `src/shared/assets/fonts/OFL.txt`이며 앱 배포물에도 포함합니다.
- `pnpm icons:generate`는 SVG에서 512px PNG와 16·24·32·48·64·128·256px을 담은 Windows ICO를 생성합니다. `pnpm build`에서 자동 실행하며 생성 파일은 `build/icons`에 있습니다.

## 정산 작업

### 앱 안에서 따라 하기

왼쪽 아래의 **사용 안내**를 누르면 현재 작업 화면 위에 8단계 튜토리얼이 열립니다. 앱 시작 시에는 기존 작업 화면으로 진입합니다.

- 정산월 선택 → 엑셀 가져오기 → 거래 확인 → 별도 지출 → 통장 출금 연결 → 정산·배분 → 마감·엑셀 출력 → 백업·복원 순서입니다.
- 단계별로 해당 버튼을 표시하고, 현재 선택한 달의 거래·미확정 건수·별도 지출·연결·마감 상태를 보여줍니다. 작업 버튼은 실제 파일 선택·거래 상세·지출 입력·영수증·연결·배분 설정·백업 창으로 연결됩니다.
- 작업을 열면 안내가 접혀 공간을 확보합니다. 안내 펼치기·이전·다음·목차로 자유롭게 이동하며, 필요 없는 별도 지출·연결 단계는 건너뛸 수 있습니다.
- **현재 장부에서 실제 자료로 진행하는 안내**입니다. 실제 저장·연결·마감·백업은 각 기능의 확인과 저장 버튼으로 수행합니다. 안내를 읽거나 단계를 넘기는 동작은 정산 자료를 생성하지 않습니다.
- 닫아도 같은 앱 실행 동안에는 보던 단계를 이어볼 수 있습니다. 안내를 마친 뒤 다시 열면 첫 단계부터 시작합니다. 앱을 재시작하면 안내는 닫힌 상태로 초기화됩니다.

### 매달 진행할 순서

1. 거래 상세에서 정산월·분류·정산 항목·지출 구분을 지정합니다. 누락 금액은 실제 자료로 입금·출금을 보정하고 사유를 기록합니다. 실제 0원과 미확인 빈칸을 구분합니다.
2. 월별 정산의 **분류·확인**에서 여러 통장 거래를 선택해 일괄 분류·확정할 수 있습니다. 한 건이라도 검증에 실패하면 전체 변경을 취소합니다.
3. **항목·분류 규칙**에서 반복 조건을 저장합니다. 등록 순서대로 첫 일치 규칙을 제안하고 이미 분류한 기록을 덮어쓰지 않습니다. 가져오기와 자동 제안은 같은 DB 트랜잭션에서 저장합니다. 제안은 미확정 상태이며 담당자가 확인해야 합니다.
4. **지출 추가**에서 통장에 없는 지출을 기록합니다. 사용일과 정산월은 별도로 설정합니다. 저장한 지출의 **영수증**에서 파일을 첨부·열기·제거합니다. PNG·JPEG·WebP·PDF를 파일당 20MB까지 지원하며 원본을 앱 데이터 폴더에 복사합니다.
5. 별도 지출의 **연결**에서 지출로 분류한 통장 출금과 금액을 연결합니다. 여러 지출을 카드대금 한 건에 연결하거나 부분 금액만 연결할 수 있습니다. 지출·통장 출금 각각의 금액을 넘는 연결은 거부합니다.
6. 차트의 일별·항목별 막대를 누르면 아래 목록이 해당 자료로 좁혀집니다. 월별 막대를 누르면 해당 정산월로 이동합니다. 목록의 상세에서 원본이나 별도 지출을 엽니다.

### 계산 기준

- 정산 수입 − (현금 + 카드 + 기타 지출) = 정산 잔액입니다. 이체·정산 제외는 반영하지 않으며 정산 제외는 사유가 필요합니다.
- 별도 지출은 해당 지출의 정산월에 사용액을 반영합니다. 통장 지출은 **보정 출금 − 연결 금액**만 반영합니다. 예를 들어 9월 카드 사용 90,000원을 10월 카드대금 100,000원에 연결하면 9월 사용액 90,000원과 10월 잔여 출금 10,000원을 반영합니다. 연결 금액에 해당하는 사용액은 10월에 다시 비용으로 잡지 않습니다.
- 미확정 제안도 금액이 있으면 잠정 합계에 포함합니다. 미분류·미확정·금액 누락이 하나라도 남으면 월 마감을 막습니다.
- **배분 설정**에서 매월 대상 1~20명의 이름을 직접 입력하고, 비율(0.01% 단위, 합계 100%)과 원 미만 처리 방식을 저장합니다. 처음 열면 이름이 비어 있는 두 입력란에 80:20 비율이 제안됩니다. 설정을 저장하면 정산에 배분액이 표시됩니다.
- 기본은 각 몫의 원 미만을 버린 뒤 소수 잔여가 큰 대상부터 1원씩 배분하는 방식입니다. 동률은 대상 순서이며, 마지막 대상에게 나머지를 주는 방식도 선택할 수 있습니다. 정수 계산으로 배분 합계와 정산 잔액을 일치시킵니다. 음수 잔액은 같은 기준의 손실 배분입니다.

### 마감과 출력

- **이번 달 마감**은 계산 기준·내역·배분액을 스냅샷으로 보관하고 수정과 추가 가져오기를 막습니다. 연결된 다른 달의 거래를 변경해 마감 결과에 영향을 주는 작업도 막습니다.
- 재개방에는 사유가 필요하며 이전 마감본은 보존합니다. 수정·삭제·연결·설정·마감·재개방의 변경 전후 이력을 남깁니다. 화면에서 50건씩 이전 이력까지 조회하며 전체 이력을 DB와 백업에 보관합니다.
- **정산표 엑셀 출력**은 기존 양식의 A:E 수입, F:H 현금, I:K 카드, L:N 기타 배치와 소계·총지출·잔액·배분 영역을 사용합니다. 내역이 많으면 영역별 행을 늘립니다. 원본 양식의 첫 행 포함 범위 불일치는 동일한 집계 기준으로 고쳤습니다.
- 잠정 출력에는 상태와 확인할 건수를 표시합니다. 마감 후에는 보관한 마감본을 사용하며, 이력의 **이 마감본 엑셀 출력**으로 이전 마감 결과도 출력합니다. `정산 상세` 시트에 포함·제외 자료와 연결 금액·사유를 함께 제공합니다.

## 엑셀 가져오기

1. **파일 가져오기**에서 은행의 `.xlsx` 파일을 선택합니다.
2. 계좌 이름, 시트, 가져올 월을 선택하고 누락·제외 행 안내를 확인합니다.
3. **N건 저장**을 누르면 선택한 월의 전체 거래가 저장됩니다. 미리보기는 월별 최대 5건입니다.

현재 `거래일시`, `출금`, `입금` 열이 있는 은행 양식과 `거래일자`, `출금액`, `입금액` 등의 열 이름을 지원합니다. 파일명에 적힌 월이 아닌 실제 거래일로 구분합니다. `.xls`, CSV, 암호가 걸린 엑셀, 임의 열 매핑은 지원하지 않습니다. 파일당 10MB, 시트 20개, 시트당 20,000행·64열 이하로 제한합니다.

- **계좌 이름은 중복 판단의 범위**입니다. 같은 계좌에는 같은 이름을, 다른 계좌에는 다른 이름을 사용합니다. 이름을 바꾸면 다른 계좌로 취급됩니다.
- 완전한 거래는 거래일시·금액·잔액·거래 내용 등을 대조합니다. 한 시트에 동일한 거래가 여러 번 있으면 그 건수는 보존합니다.
- 금액 또는 잔액이 불완전한 거래는 같은 파일의 같은 행일 때만 중복 제외합니다. 다른 파일의 불완전한 거래를 임의로 합치지 않습니다.
- 누락·잘못된 금액은 `null`과 확인 사유로 저장하고 실제 0원과 구분합니다. 입출금이 모두 양수인 행도 확인 대상으로 표시합니다.
- 거래일시가 잘못된 행은 미리보기에서 알리고 저장 대상에서 제외합니다. 파일 하단 합계는 거래로 가져오지 않습니다.
- 원본 셀 값, 파일명, SHA-256, 시트·행 번호와 가져오기 결과를 보관합니다. 원본 XLSX 파일 자체를 별도로 복사하지는 않습니다.
- 저장은 트랜잭션 단위입니다. 도중에 오류가 나면 해당 가져오기 전체를 취소하고 미리보기에서 다시 시도할 수 있습니다.

## 엑셀 내보내기

거래내역 화면에서 정산월을 선택한 뒤 **엑셀 내보내기**를 누르면 저장 위치와 파일 이름을 고를 수 있습니다. 검색·필터·현재 페이지와 관계없이 선택한 달의 전체 거래를 출력합니다.

- `거래내역`: 거래일시, 계좌, 입출금·잔액, 내용·메모, 확인 사항과 원본 출처. 금액은 숫자, 거래일시는 날짜 셀로 저장하며 누락 금액은 빈 셀로 유지합니다.
- `월별 요약`: 전체 거래 수, 확인 필요 건수, 확인된 입출금 합계와 차액. 금액 미확인 거래가 있으면 차액은 비워 두고 부분 합계임을 설명합니다.
- 텍스트는 수식으로 변환하지 않습니다. 헤더 행 고정과 숫자·날짜 형식을 적용합니다.
- 임시 파일을 완성한 뒤 선택한 파일을 교체합니다. 취소하거나 저장에 실패하면 DB는 변경하지 않습니다.

거래내역 엑셀은 원본 거래 출력용입니다. 정산 결과는 월별 정산의 **정산표 엑셀 출력**, 복원 가능한 전체 자료는 **백업·복원**을 사용합니다.

## Windows 자동 업데이트

자동 업데이트가 포함된 Windows 설치본은 실행 후와 실행 중에 [GitHub 최신 릴리스](https://github.com/lighteko/chagok/releases/latest)를 확인하고 새 안정 버전을 자동으로 내려받습니다. 설치 준비가 되면 앱을 종료할 때 설치하거나, 왼쪽 아래 **업데이트 → 재시작 및 설치**를 눌러 바로 적용할 수 있습니다. 같은 메뉴에서 업데이트를 직접 확인할 수도 있습니다.

0.2.0처럼 자동 업데이트가 도입되기 전에 설치한 버전은 자동 업데이트가 포함된 설치 파일을 한 번 직접 실행해야 합니다. Windows 릴리스에는 같은 NSIS 빌드에서 생성된 설치 파일, `latest.yml`, `.blockmap`을 함께 올립니다.

## MCP 연결

1. 차곡 왼쪽 아래 **MCP 연결 → 연결 켜기**를 누릅니다.
2. 같은 PC에서 실행하는 MCP 클라이언트에 **Streamable HTTP** 서버를 추가합니다. 차곡에 표시된 `http://127.0.0.1:<포트>/mcp` 주소를 입력하고, **토큰 복사**로 받은 값을 Bearer 토큰으로 등록합니다. 클라이언트에서 HTTP 헤더를 직접 설정한다면 `Authorization: Bearer <토큰>`을 사용합니다.
3. AI에 거래 분류를 맡기려면 연결을 켜기 전에 **거래 분류 및 규칙 관리 허용**을 체크합니다. 이 권한은 해당 연결에서만 유효하며 차곡은 건별 승인 없이 변경을 저장합니다.

- `list_transactions`는 원본 거래월(`month`, `YYYY-MM`)을 기준으로 월 합계와 페이지별 거래를 반환합니다. `search`, `filter`(`all`, `deposit`, `withdrawal`, `review`), `page`(0부터 시작)를 선택할 수 있습니다.
- `get_monthly_settlement`는 정산월(`month`, `YYYY-MM`)의 수입·지출, 순액, 확인 필요 건수, 배분 금액을 반환합니다. 마감한 달에는 저장된 마감본을 사용합니다.
- `list_transactions_for_classification`은 정산월의 미분류 거래와 사용할 수 있는 정산 항목을 조회합니다. `status: "pending"`이면 미확정 분류도 포함합니다. 분류 후 첫 페이지를 다시 조회하면 변경된 목록에서 빠진 거래를 건너뛰지 않습니다.
- `list_classification_rules`는 적용 순서대로 반복 거래 규칙과 현재 수정 버전을 조회합니다.

분류 및 규칙 관리 권한이 있는 연결에서는 다음 도구도 사용할 수 있습니다.

- `apply_classification_rules`는 지정 월에 등록된 규칙을 적용합니다. 금액과 조건이 맞으면 바로 확정합니다. 금액이 맞지 않거나 원본에 확인 필요 사항이 있으면 미확정 제안을 남깁니다. `confirm: false`로 제안만 저장할 수 있습니다.
- `classify_transactions`는 한 정산월의 거래를 최대 50건까지 분류하여 저장합니다. 기본값은 확정이며, 불확실한 거래는 `confirmed: false`로 제안을 남길 수 있습니다. 미확정 분류를 바꿀 때는 조회한 `revision`을 `expectedRevision`으로 전달합니다.
- `save_classification_rule`은 반복 거래 규칙을 생성·수정·비활성화합니다. 새 규칙에는 고유한 `id`를 지정하고, 수정 시에는 조회한 `revision`을 `expectedRevision`으로 전달합니다.

분류와 규칙 변경은 수정 이력에 기록됩니다. 분류 도구는 마감된 월과 이미 확정된 거래를 보호하며, 조회한 뒤 거래가 수정되었으면 최신 상태로 다시 조회할 수 있도록 오류를 반환합니다. 금액 단위는 원입니다.

연결은 기본으로 꺼져 있습니다. **연결 끄기**, 앱 창 닫기 또는 장부를 백업에서 복원하면 연결이 종료됩니다. 다시 켤 때는 표시된 주소와 새 토큰을 클라이언트에 등록합니다. 연결된 클라이언트가 읽은 장부 내용을 처리하는 방식은 해당 클라이언트의 설정을 따릅니다.

## 전체 백업·복원

- **백업·복원 → 전체 장부 백업**에서 `.chagok` 파일로 저장합니다. SQLite의 일관된 스냅샷으로 WAL의 최신 거래까지 포함하고, DB가 참조하는 영수증 원본과 SHA-256 검사 값을 함께 저장합니다.
- 백업은 gzip으로 압축한 단일 파일이며 암호화하지 않습니다. 금융 자료가 포함되므로 보관 위치를 선택하고 다른 드라이브나 외부 저장장치에도 복사해 주세요. 압축 해제 기준 최대 250MB를 지원합니다.
- 복원은 별도 준비 폴더에서 형식·DB 구조·SQLite 무결성·외래 키·영수증 수·파일명·크기·검사 값을 먼저 확인합니다. 잘못된 파일은 현재 장부를 변경하지 않고 거부합니다.
- 검증한 백업의 시각과 거래·지출·영수증 수를 보여준 뒤 교체를 확인합니다. 취소 시 현재 장부를 유지합니다. 복원 후 화면을 다시 불러옵니다.
- 현재 저장소를 `userData/before-restore-<UUID>`로 보관한 뒤 교체하며 실패 시 원위치로 되돌립니다. 교체 중 앱이 종료되면 복구 기록을 읽어 다음 실행 시 기존 저장소를 복원합니다. 복원 전 보관본은 자동 삭제하지 않습니다.

## 데이터 저장

- 위치: Electron `app.getPath("userData")/storage/chagok.sqlite`. 설치 폴더·Chromium 캐시와 분리합니다.
- 메인 프로세스의 내장 `node:sqlite`를 사용합니다.
- 스키마 v1: 화면 설정. v2: 가져오기·원본 거래. v3: 분류·보정, 별도 지출, 연결, 항목·규칙, 월별 설정·마감본, 수정 이력, 영수증 메타데이터. 기존 자료를 보존하며 트랜잭션으로 마이그레이션합니다.
- WAL, `synchronous=FULL`, 외래 키·고유 제약과 매개변수 SQL을 사용합니다.
- 렌더러에는 허용한 IPC 기능만 노출합니다. 임의 경로나 SQL은 전달하지 않습니다.
- 이전 localStorage 설정은 한 번 이관하며 새 값은 SQLite에 저장합니다. 저장 실패는 UI에 표시하고 재시도를 제공합니다.
- DB를 열지 못하면 기존 파일을 보존합니다. 자동으로 삭제하거나 초기화하지 않습니다.
- 금융 원본, DB 및 WAL/SHM 파일, 백업, `.env`, 테스트 산출물은 Git에서 제외합니다.

## 구조

차곡은 UI 구성 요소(`atomics`), 업무 기능(`domains`), 공통 코드(`shared`)를 분리합니다.

```text
src/
  app/                         React 진입점과 전역 테마
  atomics/
    atoms/                     공식 shadcn 컴포넌트 (CLI로 생성)
    molecules/                 MonthSelector 등 도메인 중립 UI 조합
    templates/                 WorkspaceLayout 등 레이아웃 조합
  domains/
    dashboard/                 차곡 메뉴, 작업 화면과 설정 상태
    transactions/              거래 목록·상세·가져오기 UI, 조회 훅, 순수 은행 양식 파서
    expenses/                  별도 지출·통장 연결·영수증 UI
    settlement/                계산·배분 로직, 대시보드·규칙·마감·정산표 조합
    tutorial/                  안내 단계·실제 자료 상태·단계별 작업 안내 UI
  shared/                      IPC 계약, 공통 타입·훅·유틸리티
  main/imports/                파일 선택 후 읽기와 미리보기 세션
  main/storage/                SQLite 마이그레이션과 저장소
  main/receipts/               영수증 파일 검증·복사·열기
  main/backups/                전체 백업·복원·복원 중단 복구
  main/exports/                원본 거래·정산표 엑셀 저장
  main/mcp/                    로컬 MCP 연결과 장부 조회 도구
  main/updates/                Windows 업데이트 확인·다운로드·설치
  preload/                     제한된 IPC 브리지
```

기본 UI는 공식 shadcn `base-nova` 레지스트리 소스를 사용합니다. 새로운 기본 컴포넌트는 `pnpm exec shadcn add <이름>`으로 추가하며 `components.json`이 `atomics/atoms`에 배치합니다. 도메인 컴포넌트는 이 UI를 조합하고, `atomics`와 `shared`는 `domains`나 `app`에 의존하지 않습니다. ESLint로 경계를 검사합니다.

TanStack Query는 사용하지 않습니다. 도메인 훅이 IPC 요청, 로딩·오류·재조회와 오래된 응답 무시를 관리합니다. 파일과 DB 접근은 main에 둡니다. 경로 별칭은 `@/* → src/*`입니다.

## 실행과 검증

Node.js 22.13 이상, pnpm 10.26.1을 사용합니다.

```sh
corepack enable
pnpm install
pnpm dev
```

```sh
pnpm lint           # 코드와 의존성 경계
pnpm type-check     # Electron / React 타입 검사
pnpm format:check
pnpm build
pnpm start
pnpm test:smoke     # 실제 Electron에서 설정·이관·저장 실패·재시작 검증
pnpm test:imports   # XLSX 가져오기·중복·기간·롤백·검색·복원·내보내기 검증
pnpm test:ledger    # 정산 계산·연결·영수증·차트·마감·정산표·백업과 실제 UI 검증
pnpm test:tutorial  # 사용 안내 8단계를 실제 거래 입력부터 백업까지 따라가며 검증
pnpm test:mcp       # MCP 인증, 거래·정산 조회, 규칙과 자동 분류 검증
pnpm test:update    # Windows 패키지의 자동 업데이트와 파일 무결성 검증
pnpm build:dir      # Windows 실행 폴더
pnpm build:win      # Windows NSIS 설치 파일
```

테스트는 매번 별도의 프로필과 합성 엑셀을 만들며 실제 사용자 DB를 건드리지 않습니다. 로컬에서 `CHAGOK_EXAMPLE_XLSX` 환경 변수를 지정하면 해당 첨부 파일도 격리된 프로필에서 검증합니다. 실제 원본은 저장소에 포함하지 않습니다.

Windows CI 템플릿은 `docs/windows-ci.example.yml`입니다. 자동 실행은 Workflow 쓰기 권한이 있는 인증으로 `.github/workflows/ci.yml`에 복사해 활성화합니다. 배포용 코드 서명과 아이콘은 아직 설정하지 않았습니다.
